## 4. Deployment readiness: not ready for `main` yet

Pushing to `main` deploys to production automatically.

**Blocker: production's database target is unverified.** The new code reads the new columns everywhere (for example `workflow` in every creative list). If Vercel Production's `DATABASE_URL` points anywhere other than the migrated `cyntique_demo`, **the app will fail on page loads, not just on writes.** The value can't be revealed, so either:
- **(a)** re-enter `DATABASE_URL` in Vercel for Production (and Preview) with the same value as your local `.env`, or
- **(b)** deploy a Preview first and confirm it works (below).

**Also needed before relying on production** (not blockers for a preview):
- `BLOB_READ_WRITE_TOKEN` set in Vercel for Production and Preview. Without it the uploader shows "uploads aren't set up" and nothing can be submitted.
- `SESSION_SECRET` in Vercel (it exists if login works today). Consider rotating it to end sessions issued before the password rotation.
- `LOGIN_RATE_LIMIT=enabled` in Vercel, set **after** the new code is live. Until then the limiter stays off on Vercel; nothing breaks.
- Browser testing of the M3 flow on the Preview.

Build compatibility:
- Vercel runs `prisma generate && next build`. **No migrations run on deploy.**
- There is no `engines` field (local: Node 24, npm 11.19), so the build uses Vercel's default Node version.
- npm 11 lists dependency install scripts (prisma, esbuild) for approval. The project's own `postinstall` and `build` both run `prisma generate`, so the client is generated regardless.

**Recommendation: push to a feature branch first** (Vercel creates a Preview deployment), test there, then merge to `main`.
